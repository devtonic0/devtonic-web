# Architecture

## Layers

| Layer | Path | Role |
|---|---|---|
| UI shell | `src/App.jsx` | rc-dock layout, toolbar, project picker, tab registry (`TABS`) |
| Panels | `src/panels/*.jsx` | Independent React components; talk to each other only through the event bus |
| Store / bus | `src/store.js`, `src/routing.js` | `projectRoot`, `devtonic.config.json` IO + watcher, settings, tiny pub/sub `bus`. The mission watcher watches the config file itself (the shim's polling `fs.watch` tracks the watched path's mtime, so a directory watch never fired on edits). Config IO, project switching and `routing.js` tier selection are unit-tested under `node --test` via `test/helpers/store-env.mjs`, which installs a Node-backed `window.require` with a temp `HOME` |
| Model routing | `src/routing.js`, `src/llm.js` | `⚡ auto` router: picks model tier per prompt; reads `~/.hermes/config.yaml` |
| Platform shim | `src/platform/shim.js`, `modules.js` | Browser stand-ins for `fs`, `os`, `path`, `child_process`, installed as `window.require`. There is no `electron` module: requiring it (or anything else) throws `MODULE_NOT_FOUND` with a migration hint pointing at `web.js`. Resolution logic lives in `modules.js` and is unit-tested. All fs IO is async: `fs.promises` (`fs-async.js`) is a fetch-based Node `fs/promises` subset over the `/api/fs` RPC that never blocks the main thread, and the shim fetches the `/api/env` snapshot once at startup (top-level await in `shim.js`). There is no synchronous XHR. The old sync methods (`readFileSync`, `existsSync`, ...) still exist on the shim's `fs` but throw `ERR_SYNC_FS_REMOVED` with a pointer to the `fs.promises` equivalent, and `window.process.kill()` returns a Promise. A test fails if `src/` reintroduces `XMLHttpRequest` or a `*Sync(` fs/child_process call. Mission-backed panels share the `useMission()` hook (`src/panels/use-mission.js`: async load, reload on project switch, drops stale out-of-order loads). Secrets' env-file discovery and edits live in the DOM-free `src/panels/secrets-model.js`, tested against Node and the shim. `store.js` mission IO (`loadMissionAsync`, `saveMissionAsync`, `scanTreeAsync`, `readFileSafeAsync`, async `chatContext()`) uses only standard `fs/promises` methods, so it is tested against both real Node and the shim. App's background-worker report poller uses `src/platform/worker-reports.js` (IO-injected, tested on both backends). `fs.watch` polls the path's mtime every 2 s asynchronously (`createAsyncMtimePoller` in `watch-model.js`, overlapping ticks skipped) and reports Node-style `("change"|"rename", basename)` events; watch files, not directories |
| Web platform | `src/platform/web.js`, `web-model.js` | Browser-native replacements for the old Electron APIs: `openExternal` (new tab, falling back to the OS opener via the bridge), `copyText`, `reloadApp`, `setUiScale`, `pickFolder`/`pickFile`, and Web Notifications (`notify`, `requestNotifications`). Built-in panels import these directly. Pure logic (URL scheme allow-list, notify gating, scale clamping) is unit-tested |
| File/folder picker | `src/platform/picker.js`, `picker-model.js` | In-app directory browser behind `pickFolder()` / `pickFile()` in `web.js`; lists via the bridge's `readdir` (`fs.promises`). Pure path/filter logic lives in `picker-model.js` and is unit-tested |
| Process listing | `src/platform/procs.js`, `procs-model.js` | Cross-platform `listProcesses`, `processStat` and `listeningPorts` used by Tasks, Processes and Servers. It sticks to POSIX `ps -A/-U -o col=` flags and sorts in JS, because procps' `--sort` and `--no-headers` don't exist on macOS. Ports come from `ss -ltnp` on Linux and from `lsof -iTCP -sTCP:LISTEN -Fpn` on macOS (also the Linux fallback when `ss` is missing). Parsers are unit-tested, and one test runs the real `ps` |
| Hermes binary | `server/hermes.mjs`, `src/platform/hermes.js` | The bridge resolves the agent CLI (`DEVTONIC_HERMES` → `PATH` like `which` → `~/.local/bin`, `~/.hermes/bin`, `/opt/homebrew/bin`, `/usr/local/bin`) and returns it as `hermes: {path, source, found}` in `/api/env`. Panels call `hermesPath()` at spawn time; Setup calls `refreshHermes()` after installing so new spawns pick up the binary. The resolver is unit-tested |
| First-run onboarding | `src/platform/onboarding-model.js`, `src/panels/Setup.jsx` | DOM-free model (unit-tested) classifies the bridge's resolution as `ok` / `missing` / `bad-override` (a `DEVTONIC_HERMES` path that isn't executable), builds per-platform manual install steps (install script, PATH hint, `hermes model`, `DEVTONIC_HERMES` for other agent builds, docs link) and package-manager hints for missing system tools, and decides wizard vs banner. The blocking Setup wizard shows only on a first run without an agent (copyable steps, optional "run the installer", re-check); after "skip for now" a non-blocking `AgentBanner` stays above the dock until the agent is found or dismissed for the session, and can reopen the wizard. Covered by a second UI smoke case that boots the bridge with a nonexistent `DEVTONIC_HERMES` |
| Code splitting | `src/panels/lazy.jsx`, `src/panels/code-langs.js` | Heavy panels load as separate chunks. `lazyPanel()` wraps `React.lazy` with a Suspense placeholder and an error boundary that offers a reload if a chunk fetch fails. Map (force-graph/d3) and Code (CodeMirror) are lazy in `TABS`. Inside the editor, each CodeMirror language pack (plus emmet for HTML/JSX/TSX) is a dynamic import, swapped in through a `Compartment` once it arrives. `langKeyFor()` is unit-tested, and `test/bundle-budget.test.mjs` fails if any built JS chunk is over 800 kB |
| Browser panel | `src/panels/Browser.jsx`, `src/platform/frame-model.js`, `server/frame-check.mjs` | `<iframe>` preview with its own back/forward stack. Before framing a URL it asks the bridge (`/api/frame-check`) whether the response's `Content-Security-Policy: frame-ancestors` / `X-Frame-Options` headers forbid embedding by the UI's origin; blocked sites show an "Open in new tab" card (with "Try anyway"). URL normalisation, the nav stack and the header verdict are pure and unit-tested |
| UI smoke test | `test/ui-smoke.test.mjs`, `test/helpers/cdp.mjs` | Dependency-free (only `ws`) headless-Chrome driver over the DevTools Protocol. Boots the bridge on a fixture `HOME` with a demo project, activates every default rc-dock tab plus the menu-only panels (Workspace, Settings, Help), waits for each active pane to render, lets polling panels tick, then asserts no `console.error`, uncaught exceptions or `Log` errors. Runs in CI after `npm run build` using the runner's preinstalled Chrome |
| Bridge server | `server/index.mjs` | Static host + `/api/env`, `/api/fs` (RPC), `/api/exec` (buffered), `/api/proc` (WS streaming spawn), `/api/frame-check`, `/api/agent/*` (agent API proxy, `server/agent-api.mjs`) |

## Project contract: `devtonic.config.json`

Lives at the project root. Holds `phases`, `features`, `architecture`, `todos`, and `notes`. The agent is told about it through `chatContext()` in `store.js` on every turn. Architecture, Features, Flow and Progress all re-render on the `mission` bus event.

## Agent integration

The Chat panel prefers the agent's HTTP API (Hermes / devtonic-agent `api_server`) and falls back to the CLI.

**Agent API (structured streaming).** `server/agent-api.mjs` mounts `/api/agent/*` on the bridge:

- `GET /api/agent/status` probes `GET /health` and `GET /v1/capabilities` and returns `{available, reason, url, keySource, version}` (`reason`: `ok | disabled | unreachable | no-key | unauthorized | unsupported`). Never includes the key.
- `POST /api/agent/chat {session, message, instructions?, model?, provider?}` ensures the agent session exists (`GET /api/sessions/{id}`, else `POST /api/sessions {id}`) and pipes `POST /api/sessions/{id}/chat/stream` back as SSE unchanged. `instructions` (the mission context from `chatContext()`) goes as the agent's ephemeral `system_message`, so it is not stored in the session transcript, and the agent keeps the conversation history server-side (no transcript replay as in the CLI path). If the browser disconnects, the upstream request is aborted, which interrupts the run. Errors before streaming come back as JSON with `code: agent_unreachable | agent_error | bad_request`.
- `POST /api/agent/runs/:id/stop` and `POST /api/agent/runs/:id/approval {choice, request_id?}` forward to `/v1/runs/:id/stop|approval` (run ids are validated, approval bodies are reduced to `choice` + `request_id`).
- `POST /api/agent/enable` turns the API on: when no key is configured anywhere (`keySource: none`) and the API isn't disabled, it writes a random 32-byte hex `API_SERVER_KEY` into `$HERMES_HOME/.env` (created mode 0600, other lines kept) and returns `{ok, file, restart: true}`; otherwise `409 {code: has-key | disabled}`. The key is never returned; `agentConfig()` re-reads the `.env` on every request, so the bridge uses it right away. The running gateway still needs a restart to start its API server.
- `POST /api/agent/restart` runs `<hermes> gateway restart` through `execFile` (no shell; the CLI is the one `resolveHermes()` found, so `DEVTONIC_HERMES` is honoured) with a 60 s timeout and returns `{ok, output}` (stdout/stderr tail) or `{ok:false, code}`: `409` for `disabled` / `no-hermes`, `502` for `failed` / `timeout`. `GET /api/agent/status` adds `restartable` (API not disabled and a CLI was found), which gates the button in the UI.
- `POST /api/agent/sessions/:id/model {model, provider?}` pins the session's model: it ensures the session exists, then forwards to the agent's `POST /api/sessions/{id}/model` (which persists a confirmed model lock on the session). Returns `{ok, runtime}` or `{ok:false, code, error}` with the agent's status (`409 model_lock_unavailable` when the model can't be routed; `code: unsupported` for an agent without the endpoint). Session ids and model/provider ids are validated. `GET /api/agent/status` reports `modelLock: true` only when the agent's capabilities advertise `session_model_lock`.
- `GET /api/agent/sessions?limit&offset` lists the agent's sessions (`GET /api/sessions`, recent activity first; limit clamped to 1-200) as `{ok, sessions, hasMore, offset}`. Each row goes through `sessionSummary()`, which keeps only picker fields (`id, title, preview, source, model, startedAt, lastActive, messageCount, pinned, archived`) and drops ids the chat route can't use. `GET /api/agent/sessions/:id/messages?limit` fetches the latest messages (`order=latest`, limit 1-500, default 200) and `transcriptMessages()` keeps only user/assistant turns with text (string or OpenAI-style content parts), returning `{ok, session, messages: [{role, text, timestamp}]}`. Errors map to `code: not_found | unauthorized | agent_unreachable | agent_error`.
- `PATCH /api/agent/sessions/:id {title?, pinned?, archived?}`, `DELETE /api/agent/sessions/:id` and `POST /api/agent/sessions/:id/fork {id?, title?}` forward to the agent's `PATCH`/`DELETE /api/sessions/{id}` and `POST /api/sessions/{id}/fork`. `sessionUpdateBody()` forwards only `title` (single line, ≤ 200 chars; `null`/empty clears it), `pinned` and `archived` (booleans) and rejects anything else (e.g. the agent's `hidden`/`end_reason`) with `400` before the agent is called; `forkBody()` validates the optional fork id/title. Responses are `{ok, session}` (reduced by `sessionSummary()`), `{ok, id, deleted}` and `{ok, session, parent}`; agent errors keep their status and code (`409 session_active_turn` for a delete during a running turn, `409 session_exists` for a taken fork id, `not_found`, `unauthorized`, `unsupported` for 405).

Config: `DEVTONIC_AGENT_URL` (default `http://127.0.0.1:<API_SERVER_PORT|8642>`), key from `DEVTONIC_AGENT_KEY` → `API_SERVER_KEY` env → `API_SERVER_KEY` in `$HERMES_HOME/.env` (default `~/.hermes/.env`); `DEVTONIC_AGENT_API=0` disables it. The bridge adds the bearer header, so the agent key never reaches the browser.

On the client, `src/platform/agent.js` calls these routes (status is cached for 15 s) and `src/platform/agent-stream.js` holds the DOM-free pieces: an incremental SSE parser and `reduceTurn()`, which folds `run.started`, `assistant.delta|commentary|completed`, `tool.started|completed|failed|progress` (reasoning arrives as `tool.progress` with `_thinking`), `approval.request|responded`, `run.completed|failed|cancelled`, `error` and `done` into the turn state (activity entries, transcript, streamed text, pending approval). Unknown events are ignored. Chat renders the streamed reply live, shows an approval card with the agent's `choices`, and its stop button calls `runs/:id/stop` then aborts the stream. The `api`/`cli` badge in the chat header shows the transport and why. Below the header, `agentApiHint(status)` (pure, in `agent-stream.js`) picks the fix to offer when the CLI is used: `enable` (no key: one-click `POST /api/agent/enable`), `restart` (key set but the gateway API isn't up, with a copyable `hermes gateway restart`, a **restart gateway** button when `restartable`, and a re-check), `fix-key` (key rejected, same restart button), or nothing (available, disabled on purpose, unsupported). Covered by `test/agent-stream.test.mjs` (parser + reducer) and `test/agent-api.test.mjs` (config precedence, status classification, and the real bridge against a fake agent API server, including session creation, SSE passthrough, run controls and that the key is not leaked). After a restart, `waitForAgent()` re-probes status until the API is available, the key is rejected, or ~15 s pass. **Model pinning.** With `modelLock`, Chat no longer sends `model`/`provider` on each API turn. `createModelPinner()` (`src/platform/model-pin.js`, DOM-free) pins the session's model (smart routing's tier pick, or the configured default) through the route above whenever it differs from the session's current pin, then sends the turn without a model so the agent's persisted lock applies. A refused pin falls back to per-turn `model`/`provider` and isn't retried until the pick changes; agents without the capability keep the per-turn behaviour. Covered by `test/model-pin.test.mjs` (pinner state machine, body validation, result mapping against a fake agent, and the bridge route). **Session resume.** When the API is available the session dropdown offers "resume agent session…", which opens `AgentSessionPicker` (`src/panels/AgentSessionPicker.jsx`) over `GET /api/agent/sessions`. Filtering/ordering (pinned first, then last activity), labels and relative ages are DOM-free in `src/platform/agent-sessions.js`. Picking a session fetches its transcript, converts it with `transcriptToChat()` (a leading system note, then user/hermes bubbles), writes it into that session's chat-history slot, adds the id to the project's session list and switches to it; the model pinner forgets the id so the next turn re-pins. API turns then continue the same agent session. The picker's row actions (rename, pin, archive, fork, delete) call the management routes; the fork is resumed like a picked session, and a delete calls `afterSessionDelete()` (pure) to drop the id from the project's session list and its stored chat history, switching the active session when needed. Covered by `test/agent-sessions.test.mjs` (row reduction, transcript filtering, picker helpers, a fake agent, and the bridge routes incl. key non-leak and id validation) and `test/agent-session-manage.test.mjs` (update/fork body validation, list helpers, a fake agent, and the bridge management routes). `test/agent-restart.test.mjs` covers the restart helper (fixed argv, failure/timeout mapping), the hint gating, the wait loop, and the bridge route against a fake CLI.

**CLI fallback.** When the API is unavailable (or a turn fails to start), the panel shells out per turn: `<hermesPath()> --cli -z <msg> --continue <session>`, replays the recent transcript into the prompt (one-shot mode is stateless), and tails `~/.hermes/logs/agent.log` for the live activity feed.

## Bridge protocol

- `GET /api/env` returns `{homedir, hostname, platform, env, cwd, hermes: {path, source, found}}`
- `POST /api/fs {fn, args}` returns `{ok, value}` or `{ok:false, error}`. This is an allow-listed set of `fs` functions.
- `POST /api/exec {file, args, opts}` returns `{error, stdout, stderr}`
- `WS /api/proc`: client sends `spawn | stdin | end | kill`; server sends `pid | out | err | error | close`
- `GET /api/frame-check?url=<http(s) url>` fetches the page (6 s timeout, redirects followed) and returns `{ok, status, finalUrl, blocked, reason}` or `{ok:false, error}`
- `GET /api/agent/status`, `POST /api/agent/chat` (SSE), `POST /api/agent/runs/:id/stop|approval`, `POST /api/agent/enable`, `POST /api/agent/restart`, `POST /api/agent/sessions/:id/model`, `GET /api/agent/sessions`, `GET /api/agent/sessions/:id/messages`, `PATCH|DELETE /api/agent/sessions/:id`, `POST /api/agent/sessions/:id/fork`: see Agent integration

All endpoints require the `x-devtonic-token` header or a `?token=` query param.

## Notifications

Background fix-worker completions (`~/.hermes/fix-workers/*/report.json`) always post into the chat stream. They also raise a Web Notification when the user has enabled notifications in **Settings → notifications** and the tab is hidden or unfocused. Browsers only allow the permission prompt from a click, so it is never requested at startup. Users can turn worker notifications off with the `workerNotifications` setting.

## Known v0 compromises

- Settings live in memory: `store.js` reads `~/.hermes-mission-control.json` once at boot (top-level await) into the cache in `src/platform/settings-model.js`; `loadSettings()` returns a copy from memory and `saveSettings()` updates memory synchronously, then persists through `fs.promises` with coalesced background writes (`flushSettings()` / `reloadSettings()` cover tests and external edits such as a workspace import). A crash between a save and its background write can lose that write.
- The Browser panel is an `<iframe>`, so sites that forbid framing (`X-Frame-Options` / CSP `frame-ancestors`) can't render inline. The panel detects this via the bridge and offers "Open in new tab"; pages that block framing by other means (JS frame-busting, cookie rules) aren't detected.
